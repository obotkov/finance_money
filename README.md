# Penny — учёт финансов

Учёт для нескольких людей: у каждого свои счета, операции, категории, бюджеты и аналитика.
Сайт: https://penny.place

## Устройство

| Сервис | Что делает |
| --- | --- |
| `web` | Caddy: HTTPS, страница из `web/`, прокси `/api/*` на `api`; `www.` и домены кроме `CANONICAL_HOST` (старый okayconnect.online) редиректятся на основной |
| `api` | Go-бэкенд из `backend/`: пользователи и вход, счета, операции, категории, крипто-портфели, импорт CSV, курсы валют |
| `db` | PostgreSQL 18, данные в томе `pgdata` |

Страница `web/index.html` — экспорт из Claude Design. Без входа она показывает экран входа и регистрации,
после входа берёт данные пользователя с `/api/state` и отправляет изменения в API.
Без бэкенда (например, в холсте Claude Design) показывает демо-данные.

Курсы к рублю общие для всех. Валюты — ЦБ РФ (`cbrCodes` в `backend/rates.go`; доллар и евро обязательны,
остальные — для раздела «Курсы»), монеты — CoinGecko (`coinIDs`; BTC, ETH, TON и USDT обязательны),
металлы — gold-api.com (`metals`: золото, серебро, платина, палладий, медь; цена в долларах, в базе — рубли
за грамм по курсу доллара ЦБ). Обновляются при старте и раз в час.

Раздел **«Курсы»** — таблица на всю ширину с вкладками «Валюты», «Криптовалюта», «Металлы». Валюты — курс в рублях
за столько единиц, за сколько их котирует ЦБ (100 иен, 10 лир). У монет две колонки: в рублях и в USDT; у металлов —
в рублях за грамм (медь — за килограмм) и в долларах за унцию (медь — за фунт). Дальше изменение за сутки
(у монет — в USDT: вчерашняя цена в USDT считается по рублёвым курсам монеты и USDT за тот же день; у самого USDT —
к рублю) — к последнему дню истории курсов до сегодняшнего, и кнопка «Обновить».
История у новых валют и металлов копится с первого дня, поэтому изменение за сутки у них появляется на следующий день. У валют и монет в списках есть круглый значок: для монеты это её логотип
из `web/coins/<код>.svg`, для рубля, доллара и евро — кружок с символом валюты в цвете `COIN_COLOR`
(`web/index.html`). Логотипы лежат в репозитории и отдаются нашим же Caddy — из сети ничего не грузится.
Монеты, у которых файл есть, перечислены в `COIN_LOGO` (`web/index.html`); у остальных значок
рисуется как кружок с тикером. Чтобы добавить логотип: положите svg в `web/coins/` именем в нижнем
регистре, допишите код в `COIN_LOGO` — и он появится во всех списках. Источники значков:
[web3icons](https://github.com/0xa3k5/web3icons) (MIT), кроме `doge.svg` —
[cryptocurrency-icons](https://github.com/atomiclabs/cryptocurrency-icons) (CC0). Обновляются вручную.

## Вход

Вход только через Google (нужны `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET`, иначе войти нельзя — экран входа
так и скажет). Первый вход создаёт аккаунт по почте из Google.

- Аккаунты, заведённые раньше по почте и паролю, не потерялись: первый вход через Google с той же почтой
  забирает такой аккаунт со всеми данными — пароль стирается, другие сессии завершаются.
- Сессия — cookie `session` (HttpOnly, Secure, SameSite=Lax) на 30 дней, в базе только SHA-256 токена.

### Учётки из консоли сервера

```bash
cd /opt/finance-money
docker compose exec api /api users   # список: почта, имя, способ входа, счета, операции, даты
```

«пароль, ждёт Google» в колонке входа — старый аккаунт по паролю: он откроется, когда владелец войдёт через Google
с той же почтой.

### Как включить вход через Google

1. [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → OAuth consent screen:
   тип External, название, почта поддержки; scopes `openid`, `email`, `profile`. Опубликуйте приложение
   (Publish app), иначе войти смогут только тестовые пользователи.
2. Credentials → Create credentials → OAuth client ID → Web application.
   Authorized redirect URI: `https://penny.place/api/auth/google/callback`.
3. Впишите Client ID и Client secret в `/opt/finance-money/.env` на сервере:
   `GOOGLE_CLIENT_ID=...`, `GOOGLE_CLIENT_SECRET=...` — и запустите `./deploy.sh`.

## CSV операций

Один формат для экспорта и импорта. Оба — в Настройках → «Данные»: выгрузка за выбранный период
и только нужных видов операций (расходы, доходы, переводы — в любой комбинации), с примером первых строк;
начальные остатки счетов не выбираются — они всегда в файле, иначе импорт не вернёт балансы;
загрузка — файлом (кнопка или перетаскивание; файл из русского Excel в Windows-1251 тоже читается) или вставкой CSV,
содержимое сначала показывается для проверки. Баланс в выгрузке считается по всем операциям, а фильтр применяется после.

```
Дата;Сумма (откуда);Счёт (откуда);Сумма (куда);Счёт (куда);Баланс;Категория;Описание;Тип
2026-09-14 19:42;2340,5;Тинькофф Black;;;81959,5;Продукты;Пятёрочка;расход
2026-09-10;;;142000;Тинькофф Black;84300;Зарплата;Зарплата за сентябрь;доход
2026-09-05;8433,63;Тинькофф Black;100;Валютный вклад;75866,37;;Покупка долларов;перевод
2026-09-08;4500;Наличные;;;8000;Спорт:Футбол;Секция;расход
2026-09-02;200;Binance;1;ETH;800;;Покупка 1 ETH;покупка
```

- Расход заполняет «откуда», доход — «куда», перевод — обе стороны; сумма «куда» — в валюте счёта зачисления.
- Суммы положительные, направление задают счета и тип. Тип — `расход`, `доход`, `перевод`, `покупка`,
  `продажа`; если пусто — по заполненным счетам.
- Покупка и продажа — сделка внутри крипто-счёта. У покупки слева счёт и потраченная сумма, справа код
  монеты и её количество; у продажи наоборот. Счёт должен уже существовать и быть крипто-счётом: его тип
  и валюта в файл не попадают, поэтому в пустой профиль сделка не встанет — сначала заведите счёт.
- Категория — путь через двоеточие, до четырёх уровней; при импорте недостающие создаются, без категории — «Без категории».
- Баланс — остаток на счёте операции сразу после неё (для расхода и перевода — счёт «откуда», для дохода — «куда»).
  При импорте не используется: остатки считаются по операциям.
- Начальный остаток счёта — строка с типом `остаток`: счёт в «Счёт (куда)», сумма со знаком в «Баланс».
  Экспорт пишет её для каждого счёта: сколько было на счёте до первой операции, с датой создания счёта
  или первой операции. У счёта, заведённого в приложении, это ноль — строка появляется только если остаток
  пришёл импортом. Импорт прибавляет её к остатку счёта, не создавая операцию.
  Пример: `2026-04-01;;;;Кредитная карта;-18200;;Начальный остаток;остаток`.
- Разделитель — `;` или табуляция (вставка из таблицы); поле с `;` или кавычками — в кавычках. Дата — `2026-09-15` или `15.09.2026`,
  со временем или без: `2026-09-15 14:30`, `15.09.2026 14:30:05`, `2026-09-15T14:30`. Время необязательно;
  операции, добавленные в приложении за сегодня, получают текущее время. Без времени операция — последняя в своём дне.
  Строки без даты в первой колонке (заголовок, итоги) пропускаются. Импорт идёт одной транзакцией: ошибка в строке — не загружается ничего.

## Сводка

Всё считается на странице из операций, в рублях по текущим курсам:

- **Сравнение с прошлым месяцем** — доход и расход с 1-го по сегодняшнее число против тех же дней прошлого месяца.
- **Регулярные платежи** — расход с тем же названием и категорией ровно раз в месяц минимум в двух из трёх
  прошлых месяцев, сумма колеблется не больше чем на 30 %. Ожидаемый день — медиана прошлых дат. «Скоро спишется»
  показывает ближайшие 30 дней; платёж, опоздавший больше чем на 5 дней, считается пропущенным в этом месяце.
- **Прогноз** — свободные деньги (карты и наличные) минус регулярные платежи до конца месяца минус обычные траты
  в день (расход месяца без регулярных платежей, делённый на прошедшие дни), умноженные на оставшиеся дни.
  Будущие доходы не учитываются. «Можно тратить в день» — свободные деньги минус платежи, делённые на оставшиеся дни.
- **Необычная трата** — операция этого месяца от 1 000 ₽, втрое больше медианы своей категории за полгода.
- **Чистый капитал по месяцам** — текущие остатки, откатанные назад на доходы и расходы после конца каждого месяца.
- На графиках при наведении мышью (на телефоне — по нажатию) видна точка: у трат нарастающим итогом —
  сумма с 1-го по выбранный день и сколько было к тому же дню в прошлом месяце, у чистого капитала —
  капитал на конец месяца и изменение за месяц. Так же устроены график стоимости в «Криптовалюте»
  и графики «Аналитики»; у колец «Счетов» и «Отчётов» наведение на сектор или строку показывает
  его сумму и долю в центре.
- Поля дат в «Отчётах», «Аналитике» и Настройках (выгрузка, повторяющиеся операции) открывают свой календарь
  в стиле приложения, а не системный: месяц листается стрелками, у периода подсвечены дни между началом
  и концом и подписана его длина, «Сегодня» ставит текущий день. Закрывается по Esc, нажатию мимо и прокрутке.
- **Криптопортфели** — виджеты портфелей и крипто-счетов (`backend/widgets.go`). Виджет — портфель,
  крипто-счёт или вся криптовалюта: стоимость, изменение за сутки и самые дорогие монеты со своим
  изменением за сутки. Малый занимает четверть ряда (на телефоне — половину), широкий — вдвое больше
  и показывает ещё вложенное, прибыль, количество монет и график цены каждой за неделю. «Настроить»:
  что показывать, размер, сколько монет (0–10), валюта (USDT или ₽), порядок; до 12 виджетов,
  настройки хранятся на сервере (`users.widgets`, при восстановлении бекапа источники находятся по
  имени). Пока не настраивали — по малому виджету на каждый портфель и крипто-счёт (до четырёх).
  Изменение за сутки — цены монет сейчас против вчерашних дневных при нынешнем составе.
- **Ваши монеты: рост и падение** — монеты из крипто-портфелей и с крипто-счетов (без стейблкоинов),
  до четырёх сильнее всех выросших и упавших за сутки, неделю или месяц — по дневным курсам в USDT.
  У каждой — процент, цена сейчас и сколько на этом заработали или потеряли ваши монеты.
- **Бюджеты у лимита** — занятые на 80 % и больше. Лимиты пока заданы в коде (`BUDGET_LIMITS`).

В «Отчётах» (и в детализации, и «По месяцам») можно выбрать счета: по умолчанию включены все,
включая заведённые позже; «только» у счёта оставляет его одного. В отчёт идут доходы и расходы
выбранных счетов, итог подписывает, по каким счетам он посчитан. Выбор живёт до перезагрузки страницы.

Глазик у «Всего» в боковой панели (на телефоне — в «Ещё») прячет общую сумму за «••• ••• ₽»;
выбор помнит браузер.

## Счета

Счёт заводится с нулём: в диалоге только название, тип и валюта. Баланс не редактируется — его считают
операции, а стартовый остаток можно занести строкой `остаток` при импорте CSV или обычным доходом.
Валюта — рубли, доллары, евро или любая монета из списка курсов (`coinIDs` в `backend/rates.go`).
У крипто-счёта валюта — то, чем на нём расплачиваются (обычно USDT), а купленные монеты лежат
на нём же сделками, отдельных счетов под них не заводится.

Строка счёта в таблице открывает **движение по счёту**, окно счёта — только кнопка «Изменить» (она же
в шапке движения, в том числе на телефоне). Сверху — период, как в «Отчётах» (даты от и до, готовые
варианты и «Всё время»), и выбор счёта; ниже — остаток на начало и на конец периода, сколько
поступило и списано, и список событий счёта с остатком после каждого: доходы, расходы, переводы
в обе стороны, сделки (закрытая покупка — двумя строками: покупка и закрытие) и открытие счёта
с начальным остатком. Начальный остаток — текущий баланс минус все операции счёта, дата — создание
счёта или первая операция; это не поступление, поэтому в «Поступило» он не входит, а остаток на
начало = остаток на конец − поступило + списано. У крипто-счёта остатки — деньги на счёте без монет.
Нажатие на операцию открывает её изменение.

Экран «Счета»: сверху две карточки одной высоты — «Где лежат деньги» (диаграмма по типам) и «Чистый
капитал» (итог и из чего он складывается: активы, долги, свободные деньги, вклады и инвестиции,
крипто-счета с их P&L). У каждой свой переключатель валюты: ₽, $, € или USDT. Ниже таблица на всю
ширину с колонками «Счёт», «P&L», «Вложено», «Баланс». Баланс — стоимость счёта целиком (у крипто-счёта
вместе с монетами), под суммой в валюте счёта — примерно в рублях. Вложенное и P&L пока считаются
только у крипто-счетов, у остальных прочерк; вклады и инвестиции встанут туда же, когда у них появится
своя доходность. На телефоне строка превращается в карточку: у обычного счёта название и баланс,
у крипто-счёта ещё три цифры с подписями.

При удалении счёта спрашивается, что делать с его операциями:

- **Перенести на другой счёт** — в списке только счета в той же валюте, иначе суммы операций поехали бы.
  Операции переходят на выбранный счёт, к его остатку прибавляется остаток удаляемого (вместе с начальным,
  которого нет в операциях). Переводы между этими двумя счетами стали бы переводом самому себе, поэтому исчезают.
- **Удалить вместе со счётом** — операции удаляются, а остатки счетов на другой стороне переводов
  пересчитываются без них: полученное по переводу вычитается, отданное возвращается.

## Криптовалюта

Отдельный раздел меню: кошельки и биржи, которые не входят в счета и в чистый капитал.

- **Портфель** — название и подпись («биржа», «холодный кошелёк»), внутри монеты: количество
  и сумма в USDT, которую в монету вложили. Одна монета в портфеле — одна строка.
- **Баланс** — количество по текущему курсу: цена монеты в рублях, делённая на цену USDT.
  **Прибыль** — баланс минус вложенное, в USDT и в процентах. Цена покупки в строке монеты —
  вложенное, делённое на количество.
- **Крипто-счета** — счета с типом «Криптокошелёк» из раздела «Счета» показываются первой таблицей,
  над портфелями: свободный остаток счёта, внесённая сумма и стоимость в USDT с прибылью, внизу —
  итог по всем крипто-счетам. Ниже — портфели, добавленные вручную, и кнопка «Добавить портфель». Строка
  открывает страницу счёта: первой строкой свободный остаток, дальше купленные на счёте монеты
  с количеством, ценой и прибылью, а под ними движение средств — все операции по счёту.
- **Стоимость счёта** — свободный остаток плюс монеты, купленные на нём: 8 000 USDT и 1 ETH дают
  8 000 USDT плюс сегодняшняя цена этого ETH. Эта же сумма идёт в чистый капитал и в диаграмму
  «Где лежат деньги».
- **Внесено на счёт** — только то, что пришло со стороны: поступления минус списания по переводам
  с других счетов. У стейблкоина сама сумма перевода и есть внесённое: 84 000 ₽ → 1 000 USDT даёт
  ровно 1 000 USDT. У остальных берётся вторая сторона перевода — те же 84 000 ₽ по текущему курсу
  USDT, то есть цена покупки, а не сегодняшний курс монеты, иначе прибыль всегда была бы нулевой.
  Сделка внутри счёта внесённое не двигает: купили на 2 000 USDT эфира — вложено осталось прежним,
  а прибыль просто переехала в строку монеты. Остаток, пришедший импортом, операцией не является
  и во вложенное не попадает.
- Три виджета наверху считают либо все портфели и счета, либо то, во что провалились — портфель
  или счёт. Вложенное и прибыль считаются и по портфелям, и по счетам.
- **Сделка по крипто-счёту** — кнопка «Добавить сделку» на его странице: покупка, продажа, ввод и вывод.
  Покупка и продажа остаются внутри счёта: с остатка уходит (или на него приходит) сумма в валюте
  счёта, а количество монеты ложится на сам счёт. Ввод и вывод — перевод с любым другим счётом,
  и только он двигает внесённое. Цена берётся из курсов, но её можно заменить своей, и до сохранения
  видно, какими станут остаток и количество монеты. Продать можно только то, что на счёте есть.
  Дата — первой. У покупки и продажи три поля в одну строку — количество, цена за монету и «Итого»
  (сумма целиком): вводятся любые два, третье считается. Ввели количество и сумму — считается цена;
  сумму и цену без количества — количество; количество и цену — сумма. «Цена по курсу» возвращает
  текущую цену и пересчитывает сумму. В операцию уходят сумма и количество, поэтому введённая сумма
  записывается точно, без округления через цену.
  Сделка — операция с типом `buy` или `sell` (`coin` и `received` — монета и её количество,
  `amount` — сумма в валюте счёта); в доходы и расходы она не идёт, а в списке операций стоит
  в категории «Сделка». Щелчок по сделке — здесь или в «Операциях» — открывает тот же диалог
  для правки: монета, покупка или продажа, количество, цена и дата (`PUT /api/transactions/{id}`).
- **Закрытие сделки.** У открытой покупки в «Движении средств» есть кнопка «Закрыть»: указываешь
  цену закрытия (по умолчанию — текущий курс) и дату, и вся купленная монета продаётся по этой цене.
  Выручка возвращается на остаток счёта, а покупка и закрытие остаются одной строкой: цена закрытия,
  цена покупки, процент и доход или убыток по сделке. Щелчок по закрытой сделке открывает то же окно —
  там можно поменять цену и дату или отменить закрытие. Закрыть нельзя, если часть монет этой
  покупки уже продана другой сделкой. На сервере это `close` и `closeDate` у покупки; в выгрузке CSV
  закрытая сделка идёт двумя строками — покупкой и продажей.
- **График «Стоимость за 30 дней»** — под виджетами раздела, для всего раздела, портфеля или
  крипто-счёта. Крипто-счёт восстанавливается по операциям: остаток и монеты на конец каждого дня
  по курсам того дня. У портфеля истории состава нет, поэтому он считается в нынешнем составе.
  Наведение (на телефоне — касание) показывает стоимость за день и изменение ко вчерашнему.
  Курсы по дням лежат в `rate_history`: каждое обновление курсов пишет сегодняшний день, прошлые
  30 дней монет подкачиваются из CoinGecko (`/coins/{id}/market_chart`) по одной монете раз в 15 секунд,
  фиат копится с первого дня. `/api/state` отдаёт их в `history` (код → день → рубли).
- **Монеты на странице счёта** по умолчанию идут по стоимости в USDT, от большей к меньшей. Щелчок
  по заголовку колонки (монета, количество, цена, стоимость) сортирует по ней, второй — в обратную
  сторону, третий возвращает сортировку по стоимости. Щелчок по монете оставляет в «Движении
  средств» только её сделки, щелчок по свободному остатку или по фильтру — снова всё.
- **Движение средств крипто-счёта** — таблица с колонками как у монет выше: дата, количество
  (+/− монеты у сделки, «Ввод»/«Вывод» и второй счёт у перевода), цена сделки в USDT с текущей ценой
  и процентом к ней (зелёным — если это в пользу сделки: у покупки рост, у продажи падение)
  и изменение остатка счёта с тем, что оно сделало с «Вложено».
- **Сколько вложено в монету** — потраченное на неё минус вырученное. Продали дороже покупки —
  вложенное уходит в минус, и это и есть прибыль по монете. Сумма прибылей по строкам всегда
  сходится с прибылью счёта.
- Монеты — встроенные из списка `coinIDs` (`backend/rates.go`), на странице у них есть название и
  приблизительная цена для демо-режима (`COINS` в `web/index.html`). Если CoinGecko не отдал курс
  монеты, берётся последний сохранённый, а если его ещё нет — приблизительная цена из `COINS`.
- **Свои монеты.** Монету не из списка можно найти и добавить: «Добавить монету» — последняя строка
  списка в «Курсах» на вкладке «Криптовалюта», или «+ Другая монета…» в выборе монеты у покупки и в
  портфеле. Поиск идёт по CoinGecko (название или тикер, через полсекунды после ввода); у каждой
  найденной монеты — цена в долларах и рублях, чтобы отличить её от тёзок (второй запрос,
  `simple/price`, по найденным id). Ответы вместе с ценами сервер помнит 10 минут — у CoinGecko без
  ключа несколько запросов в минуту. Добавленная монета встаёт в курсы, сделки, портфели и валюты
  счетов наравне со встроенными, с логотипом CoinGecko; курс записывается сразу, история за 31 день
  догружается в фоне. Монета заводится на сервере один раз (таблица `coins`, курсы у всех общие),
  а в список человека попадает через `user_coins`. Тикер — один на сервер: монета-тёзка встроенной
  или уже добавленной («Тикер занят»), а также тикеры валют ЦБ и металлов не добавляются. Убрать
  свою монету из списка можно в том же окне («Ваши монеты»), если она не валюта счёта и её нет
  в сделках и портфелях. В демо-режиме поиск идёт прямо в CoinGecko, монета живёт до перезагрузки.

### Пулы ликвидности

Позиция в пуле с концентрированной ликвидностью (как в Uniswap v3) живёт внутри крипто-портфеля
или на крипто-счёте: «Добавить пул» в шапке открытого портфеля или счёта. Позиция — пара монет A/B, интервал цены (сколько B за одну A,
задаётся при открытии и потом не меняется) и история событий: внесение, вывод части, сбор комиссий.

- **Сколько монет в позиции сейчас** не хранится, а считается. Каждое внесение по своей цене даёт
  ликвидность L (как в протоколе — меньшая из двух по монетам; лишнее одной монеты в позицию не идёт),
  вывод снимает долю L. По суммарной L и текущей цене (по рублёвым курсам обеих монет):
  ниже интервала всё лежит в A, выше — в B, внутри — смесь. Формулы — `poolAmounts`/`poolLiquidity`
  в `backend/pools.go` и такие же в `web/index.html`.
- **Монеты ходят между позицией и портфелем.** Внесение берёт монеты из строк того же портфеля
  вместе с их вложенным (пропорционально), а чего там нет — считается новыми деньгами по курсу дня
  внесения. Вывод возвращает монеты в портфель, и вложенное позиции переезжает с ними той же долей,
  поделённое по их стоимости; комиссии приходят в портфель без вложенного — чистый доход. Поэтому
  от внесения и вывода прибыль портфеля не меняется, а одна монета не считается дважды.
- **Внести** — дата, цена (по курсу на дату или своя) и количество: вторая монета считается по первой.
  Ниже интервала вносится только A, выше — только B, внутри нужны обе. **Вывести** — 25/50/75/100 %
  или свой процент, вернувшиеся монеты считаются по формуле. **Комиссии** — сколько каждой монеты пришло.
  События идут по порядку: дата нового не раньше последнего. **Изменить интервал** — вывести всё
  и открыть новую позицию с этими монетами (интервал открытой позиции не меняется).
- В карточке: интервал с отметкой цены и статус (в интервале / ниже / выше / закрыта), монеты
  в позиции, стоимость, прибыль = стоимость − вложенное, собранные комиссии и сравнение «к простому
  хранению» — стоимость позиции против тех же внесённых монет, если бы их просто держали (выводы
  уменьшают их в той же доле). Это и есть непостоянные потери.
- Стоимость и вложенное позиций входят в портфель (итоги, виджеты, список портфелей); на графике
  за 30 дней позиция считается по ликвидности на каждый день и ценам того дня, а монеты портфеля —
  с откатом того, что события пула после этого дня забрали или вернули.
- **На крипто-счёте** монеты валюты счёта уходят в позицию с его остатка, остальные — из купленных
  на нём монет (их количество — сделки плюс события пулов счёта); внести больше, чем есть на счёте,
  нельзя — сначала купите или переведите. Вывод и комиссии возвращают монеты на счёт. Вложенное
  счёта считается по деньгам со стороны и от пула не меняется; «вложено» у позиции на счёте —
  стоимость внесённого в день внесения, только для её собственной прибыли. Позиция входит
  в стоимость счёта (а значит, в «Всего» и чистый капитал), в график счёта, а движение его валюты
  в пул и обратно — строками «Пул» в движении по счёту. Пока на счёте есть пулы, его нельзя удалить
  и нельзя сменить ему валюту или тип.
- Отменить можно последнее событие (×), удалить — всю позицию: монеты портфеля возвращаются ровно
  такими, какими были до события (каждое событие хранит, что сделало со строками монет). Несобранные
  комиссии в протоколе сайт не видит — их записывают при сборе.

## Демо-данные и очистка

В Настройках → «Демо-данные и очистка»:

- **Загрузить демо-данные** — очищает аккаунт и заполняет его за текущий год: четыре счёта
  (карта, наличные, вклад, брокерский) и около 190 операций с января по сегодня — зарплата, аренда,
  продукты, такси, подписки, переводы в накопления, вложенные категории. Счета создаются через
  `POST /api/accounts` (в CSV нет типа счёта и валюты, а типы — это сегменты диаграммы «Где лежат
  деньги»), операции — обычным импортом. Суммы одни и те же при каждой загрузке.
- **Удалить всё** — `POST /api/data/reset`: удаляет счета, операции, категории и крипто-портфели одной транзакцией
  и возвращает категории по умолчанию, как у нового аккаунта. Отменить нельзя.

## Бюджеты и уведомления

Раздел «Бюджеты»: месячный лимит в рублях на категорию расходов (`backend/budgets.go`).

- Траты бюджета — расходы категории вместе со всеми подкатегориями за календарный месяц (на сервере —
  по Москве), суммы не в рублях — по текущему курсу. Переводы и сделки не считаются.
- «Новый бюджет» — категория (из тех, где бюджета ещё нет) и лимит; в окне видно, сколько на неё
  ушло в прошлом месяце и в среднем за три. Нажатие на бюджет — изменить лимит, категорию или удалить.
  Удаление категории удаляет её бюджет.
- Полоса синяя, у порога уведомлений — оранжевая, при превышении — красная; под ней — остаток и сколько
  можно тратить в день до конца месяца. В Сводке «Бюджеты у лимита» — те, что дошли до порога.
- Уведомления (включены по умолчанию, порог 90 %): после каждого изменения данных — и после записи
  повторяющихся операций — сервер проверяет бюджеты и шлёт пуш, когда траты дошли до порога, и ещё один
  при превышении. Каждый уходит раз за месяц (`budget_alerts`); смена лимита сбрасывает отметки месяца.
- Пуш — Web Push: `web/sw.js` показывает уведомление и по нажатию открывает `/?screen=budgets`.
  Ключи VAPID сервер создаёт при первом запуске и хранит в `server_settings`, подписки браузеров —
  в `push_subscriptions` (отозванные удаляются при отправке). «Включить уведомления» спрашивает
  разрешение браузера и подписывает это устройство; «Прислать пробное» проверяет доставку.
- На iPhone и iPad пуши приходят только сайту, добавленному на экран «Домой» (iOS 16.4+): для этого
  у страницы есть `manifest.webmanifest` и иконки в `web/icons/`.
- Бюджеты входят в бекап (`budgets` в файле); порог уведомлений и подписки — нет.
- Демо-режим: бюджеты и порог меняются в памяти страницы, пуши недоступны.

## Повторяющиеся операции

В Настройках → «Повторяющиеся операции»: расход или доход на счёт с частотой — каждый день, неделю,
две недели, месяц, квартал или год. Поля: счёт, сумма (в валюте счёта), частота, категория,
описание (пусто — название категории) и дата первого раза (по умолчанию сегодня).

- Операции записывает сервер (`backend/recurring.go`) в день срока по Москве: при запуске и дальше
  каждые 15 минут. Это обычные операции через `insertTx` — остаток счёта меняется, как при ручной
  записи, в аналитике они не отличаются от остальных. Операция без времени.
- n-й срок — дата первого раза плюс n шагов, а не прошлый срок плюс шаг: 31 января → 28 февраля →
  31 марта; 29 февраля раз в год → 28 февраля в невисокосный год.
- Если первый раз в прошлом, операции за прошедшие сроки записываются сразу при сохранении (форма
  показывает, сколько и за какие даты, и спрашивает подтверждение); больше 400 разом — отказ.
- Правка правила не трогает уже записанные операции: следующий срок считается от новой даты первого
  раза, но только после последней записанной (`last_date`), так что ничего не задваивается.
  Удаление правила оставляет записанные операции.
- Удаление счёта удаляет его правила, перенос операций на другой счёт переносит и правила.
- Правила входят в бекап (`recurring` в файле). При восстановлении они продолжаются со следующего
  срока после сегодняшнего: сроки между датой бекапа и сегодня не догоняются.
- Демо-режим: правило и операции за прошедшие сроки живут в памяти страницы, сами по срокам
  не записываются.

## Бекапы

В Настройках → «Бекапы»: сделать бекап, список сохранённых (дата, счета, операции, размер),
скачать, восстановить или удалить любой, восстановить из скачанного файла.

- Бекапу можно дать название (карандаш рядом с датой) — оно показывается вместо даты, дата уходит
  во вторую строку. До 60 символов, лишние пробелы убираются; пустое название возвращает дату.
  Название хранится только в списке (`backups.name`): в файл бекапа оно не попадает, на автоудаление
  старше 30 последних не влияет.

- Бекап — полный снимок данных пользователя: счета с остатками, категории с вложенностью и иконками,
  операции (включая сделки и закрытия), повторяющиеся операции и крипто-портфели. Хранится на сервере в таблице `backups`
  (JSON, сжатый gzip), у пользователя — последние 30, старые удаляются при сохранении нового.
- Файл — тот же JSON: `{"format": "penny-backup", "version": 1, "createdAt", "accounts", "categories",
  "transactions", "cryptoPortfolios", "recurring", "budgets"}`. Суммы записаны строками, как NUMERIC в базе, без округления.
  Ссылки между записями — по `id` из файла; при восстановлении записи получают новые id.
- Бекапы — версии данных. У пользователя хранится текущая версия (`users.current_backup_id`,
  в состоянии — `currentBackup`): бекап, с которым данные сейчас совпадают. Её ставят «Сделать бекап»
  и восстановление из списка; любое изменение данных (счета, операции, категории, портфели, импорт,
  очистка) сбрасывает её. В списке она помечена «Текущая версия», кнопки «Восстановить» у неё нет.
- Восстановление из списка переключает данные на выбранную версию и нового бекапа не создаёт.
  Изменения, которых нет ни в одном бекапе, при этом пропадают — окно подтверждения предупреждает
  об этом, когда текущей версии нет. Восстановление из файла заменяет данные так же, а текущую версию
  сбрасывает: такой версии в списке нет. Всё идёт одной транзакцией; остатки счетов берутся из бекапа
  как есть. Файл, который не встал (чужой формат, неизвестная валюта, ссылка на несуществующий счёт,
  повтор названий, цикл в категориях), не меняет ничего.
- Бекапы с пометкой «Сохранён сам перед восстановлением» остались от первой версии раздела, новые такие
  не создаются.
- Бекапы лежат в той же базе, что и данные, поэтому от потери сервера защищает только скачанный файл.
- Без сервера (демо-режим) бекапы недоступны, как и загрузка демо-данных.

## Telegram

Бот присылает сводку по финансам и файл бекапа — каждый понедельник в 10:00 по Москве
(`backend/telegram.go`, сводка — `backend/summary.go`). Включается токеном бота
`TELEGRAM_BOT_TOKEN` в `.env` на сервере (бот создаётся у @BotFather); без токена раздел
Telegram в Настройках пишет, что бот не настроен. Сервер сам забирает сообщения бота длинным
опросом `getUpdates` — вебхук и открытые порты не нужны. Пока бот не связался с Telegram
(`getMe` повторяется с паузой от 15 секунд до 5 минут), кнопки подключения нет, а раздел пишет
причину: неверный токен или сервер не достучался до `api.telegram.org`.

Если `api.telegram.org` с сервера недоступен, запросы бота можно пустить через посредника —
его адрес задаётся в `.env` как `TELEGRAM_API_URL` (вместо `https://api.telegram.org`).
Готовый посредник — Cloudflare Worker `cloudflare/telegram-proxy.js`: в панели Cloudflare
Workers & Pages → Create → Worker, вставить код, в `BOT_ID` вписать цифры токена до двоеточия,
Deploy; адрес вида `https://<имя>.<аккаунт>.workers.dev` — в `TELEGRAM_API_URL`, затем `./deploy.sh`.
Проверка с сервера: `curl https://<адрес воркера>/bot<токен>/getMe` должен вернуть `"ok":true`.

- **Подключение.** Настройки → Telegram → «Подключить Telegram»: открывается чат с ботом по ссылке
  с одноразовым кодом (15 минут), в нём нажимают «Start» — чат привязан, страница это видит сама.
  Один чат — один пользователь. Отключить — кнопкой в Настройках или командой `/stop`.
- **Команды бота:** `/summary` — сводка сейчас, `/backup` — бекап сейчас, `/stop` — отключить.
  Те же «Отправить сводку / бекап сейчас» — кнопками в Настройках.
- **Сводка** (в рублях по текущим курсам): сколько на счетах (у крипто-счёта — с монетами и пулами),
  свободные деньги (карты и наличные), крипто-портфели; доходы, расходы и итог за неделю и пять
  категорий, куда ушло больше всего; доходы и расходы с начала месяца; бюджеты у порога уведомлений
  и превышенные; повторяющиеся операции на ближайшие 7 дней. По расписанию неделя — прошлая
  (пн–вс), по кнопке — последние семь дней. Переводы и сделки в доходы и расходы не входят.
- **Бекап** сохраняется в список на сайте (с пометкой «Отправлен в Telegram», становится текущей
  версией) и уходит файлом `penny-backup-….json` — тот же, что «Скачать»; восстанавливается через
  «Восстановить из файла».
- **Рассылка** проверяется раз в 10 минут: кому на этой неделе ещё не слали, если уже наступил
  понедельник 10:00. Лежавший в это время сервер догонит рассылку, как поднимется. Подключившись
  посреди недели, первую сводку получают в ближайший понедельник. Выключить — «Нет» у «По понедельникам».
